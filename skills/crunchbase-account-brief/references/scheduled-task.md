# Recurring meeting briefs

Recurring execution is a host-dependent extension, not a connector capability. When requested, discover the host's scheduling tool and prepare a concrete task containing timezone, cadence, calendar/account scope, accepted event window, seller context, output destination and optional CRM dependency. Create/update only within the user's requested scope; a drafted prompt is not a configured schedule. Never claim success without a returned schedule confirmation.

Unattended runs reuse established inputs; do not ask questions. Missing required input or dependency produces a concise actionable failure, never invented defaults. Calendar failures do not mean there are no meetings. Resolve each external account/attendee, prepare confirmed meetings in time order, and disclose unresolved meetings. Do not manufacture partial briefs after a required data failure. Optional enrichment can be omitted with an accurate limitation if the accepted task permits it.

With no external meetings, stay quiet unless the user requested status updates. Do not send messages to third parties. A schedule output in the user's chat is not authorization for outreach. Use a supported persisted seller context or task-contained context; do not assume local files exist in a scheduled host.
