# Sales brief output

Read `output-contract.md` first. Adapt to the requested length; do not populate unsupported sections or repeat facts. Use one as-of date and accepted event window, linked canonical account, coverage/limitations, and a clear distinction among Crunchbase facts, CRM history, seller claims and your hypotheses.

When fit is inferred from company/product descriptions and seller context alone, describe it as potential fit, not strong or confirmed fit. Stronger fit language requires attributed evidence of the account’s actual needs; state what remains unconfirmed.

1. **At a glance:** what the account does, relevant current products, and funding/prediction context only when supported. A separate Why they might buy line links offering → buyer → evidence, framed as a hypothesis, plus one question that would confirm or disprove it.
2. **Pick up where you left off** for follow-ups: dated CRM/user-supplied conversation, current deal/relationship, unresolved commitments and next step. If unavailable, say so; do not invent continuity. New developments are dated after the established last meeting; otherwise label the actual covered window.
3. **What to say:** one opener and up to four distinct talking points. Each contains Fact (date/source), May mean (buyer-specific hypothesis), Offering (supported seller claim), and Suggested wording. Product-neutral mode omits Offering. Strong facts matter more than filling four points. CRM notes can motivate a follow-up question but are not an external event source.
4. **People and competitors:** confirmed attendees or explicitly labeled key people; only genuine professional common ground. Confirm competitors through product/buyer evidence and report dated moves without disparagement. Name and count each member of any pattern.
5. **Source notes and next question:** material limitations, conflicting/undated descriptions, unresolved identities, accepted partial scope and the strongest question that could change the approach.

A CRM-format result is a plain-text note to paste, not a CRM mutation. An outreach opener/email is a draft, never sent. Use the host's normal artifact format when applicable. Do not expose email/phone contacts. For JSON use `json-schema.md`, keeping notes inside the object. Display null table cells as — with the neutral legend when useful; optional empty prose sections may be omitted, but decision-relevant limitations cannot be hidden.
