# Retrieval workflow

Read the shared entity-resolution, query-core and output contracts. All field/collection names here are capability hints that require live confirmation, not reusable evidence of current schema or entitlement. Stop the dependent mode when required data is unavailable; optional missing fields may leave accounts unscored and require a coverage note.

## Account evidence

Batch-search `organizations` for confirmed identifiers with explicit projections. Required identity outputs are identifier, profile URL and website. When retrieving evidence for a positive-weight growth factor, confirm live support and request both `growth_prediction_tier` and `growth_score` for every scored account in the same organization enrichment. Normalize them as `growth_tier` and `growth_score`; use both returned values. An unrequested field is not unavailable: retrieve an omitted supported field before scoring. Use a single measurement only when live metadata shows the other unsupported, or a successful requested projection returns it null/absent; retain that limitation in the normalized artifact and disclose single-measurement coverage. Terminal authorization/service failures still stop dependent work; do not reinterpret them as permission to score with less evidence. Do not replace organization growth fields with a different prediction card opportunistically. An accepted zero growth weight adds no growth-retrieval dependency. For supplied normalized evidence or an explicit no-requery request, honor that boundary: reuse documented provenance and disclose unverified growth-field coverage rather than claiming both fields were retrieved. Other scoring projections are `heat_score`, `heat_score_delta_d90`, `funding_prediction_tier`, `last_funding_at`, `last_funding_type`, `last_funding_total`, `ipo_status`, `operating_status`, status, last_layoff_date and closed_on when available. Project short_description, employee band and micro_categories only when needed for fit/grouping. Map fields into the normalized scoring schema; unsupported optional projections must not turn into invented zeros.

When recent funding is absent, imprecise or excluded, retrieve complete eligible `funding_rounds` for confirmed organizations under live-supported predicates; request identifier, funded organization, announced date, type and USD amount. Investor `funds` can supply owner identifier, started_on and money raised, but started_on is not proof of a close. Use `last_fund_at` for scoring only when a separately returned supported field/card and source establish an actual completed fund close; otherwise retain the fund record as context and leave the financing date unknown. Count/pagination completeness applies independently to each query. Prediction tiers are forecasts, never completed financing or buying intent. Products of displayed accounts can support a tentative seller-fit hypothesis; product evidence never changes the numeric score.

## Similarity and customers

Resolve named seeds/customers with the expert resolver. Use `org_similarities` only if live contracts support it, retrieving `source`, `target`, similarity score and micro-category overlap for both forward and reverse directions. Retain direction and shared micro-industry evidence; similarity is not a symmetric probability. Enrich canonical candidate organizations after similarity discovery, enforce accepted ICP filters and exclude seeds/known customers as requested. Do not claim all neighbors were searched without paging the complete relevant set. Customer-peer bonus requires a known customer and returned overlap evidence; never award it to the customer itself.

## Completion and output

Use the helper's exact ordering and disclose the versioned rubric. Main table: canonical company, score/tier or unscored status, factual drivers, one qualified seller-fit hypothesis when requested, and source link. Include counts for requested, confirmed, unresolved, excluded, scored and unscored. Preserve unknown metrics in the machine artifact; omit irrelevant empty prose without concealing material limitations. A risk flag is a reason to review, not an automatic outreach action.

Do not use expert-generated narrative aggregates, guess identifiers, broaden empty-result filters, add external sources, create lists or write CRM records without the corresponding requested scope. For explicitly requested saved lists use the bundled saved-lists contract and stop after successful reconciliation.

## Existing-book modes

For CSV/pasted books, preserve original row identifiers and resolve each distinct company. For saved lists, select the intended list, page complete membership, then batch-enrich confirmed UUIDs. For an ICP-defined book, agree the universe before searching. Report unresolved inputs outside scored candidates; never silently lose them in an export.

Investor accounts use completed fund closes as financing events; do not count the same close twice. Keep configurable weights, tier boundaries and customer bonus from the accepted rubric. No relative-percentile tier fallback is allowed. Custom weights remain fixed across monthly comparisons; changing them establishes a new baseline. Export all confirmed rows including unscored/closed records; attach unresolved inputs separately. Tier A/B JSON/CSV can become Account Signals's book with canonical UUIDs and source as-of date retained.
